# Registry Admin and teacher CBT publishing

The main administrator selects **Registry Admin** in **Workspace → Staff** when creating or editing a staff account. The staff member signs in with the existing staff login or the learning portal login and opens the Registry workspace.

Registry Admin can manage student accounts, classes, subjects, subject allocation, terms, calendar, promotions, academic score sheets, result settings, academic records, affective records, mid-term results, reports, learning resources and CBT moderation. Financial routes and actions, the bursary portal, fee/payment/discount/expense/inventory records, whole-database backups, school profile settings and staff role management are blocked on the server, including old direct URLs. The Registry dashboard contains only academic counts and links. Role and account status are checked from the database on each request; role changes take effect for existing sessions.

The new **Academics → Scores** page supports CA/exam scores and weekly scores in the active term. It reuses existing limits, roster checks, concurrency detection, publication locks and score audit records. Reopen score entry through Result settings before changing published results. Blank fields preserve existing values; use zero to record a zero mark.

Teachers create a draft, add questions, then select **Publish assessment**. Eligible students see the assessment immediately and can attempt it during its scheduled window. Existing papers awaiting pre-approval can be published by their assigned teacher. Existing drafts and pending papers are not published automatically. Completed CBT results still require academic approval before publication or score transfer; both the main administrator and Registry Admin can review and approve completed results.

Deploy the changed PHP files, `admin/nav.html`, new shared classes, `config/staff_permissions.php`, new dashboard/score page and migration together. Run `php database/migrate.php` to apply `20261004_teacher_cbt_publishing.sql`; it only changes the default for new CBT drafts. The existing text staff-role column already supports `r`, so no staff-account schema change is needed.

To roll back: first change Registry Admin accounts to an appropriate existing staff role or disable them, then restore the previous code. Restore the assessment column default with `ALTER TABLE cbt_assessments ALTER COLUMN require_approval SET DEFAULT 1;`. Existing assessments and scores remain intact. A rollback must not rely on older code understanding the new `r` role.

Local verification: `php tests/registry_access_http_test.php`, `php tests/cbt_authoring_test.php` and `php tests/academic_creation_http_test.php`. The HTTP test uses temporary accounts and records and removes them in `finally`; the authoring test uses a disposable isolated database schema.

## CBT recovery and result corrections

Teachers can edit assessment settings from the builder while a paper is a draft, or paused with no attempts. Use **Settings & resume** for a paused paper. Once students have started, duplicate the paper for different settings. Copies of old papers receive future dates. Publishing rejects a pass mark above the actual question total.

Exam tabs check server state every ten seconds and receive revised deadlines from answer saves. Pausing prevents further answers and early submission; it does not freeze the official deadline. Cancelled and archived papers also reject answer writes. Expired attempts finalize from the exam, staff script listings, approval/publication actions, and `tasks/cbt_notifications.php`. Run that existing CLI task every minute for unattended timeout processing; without a scheduled task, the next exam or staff request performs recovery.

Changing a marked answer or reopening a script invalidates the previous result approval. Academic administration must approve the revised results and publish them again. If a previously transferred score changes, the **Score transfer** panel in academic CBT administration shows the old/new marks and an amendment form requiring a reason. Amendments respect term/weekly publication locks and refuse to overwrite a school score changed manually since the original transfer. Teacher transfer requests report that academic amendment is required.

No schema migration is required for these fixes. Deploy the shared settings form, PHP controllers/services and updated exam JavaScript together. Keep the `cbt-exam.js?v=2` cache version. Legacy MyISAM school score tables retain their engines; named locks serialize scorebook/transfer writes, with audit validation before the legacy write. A database/server crash during a legacy write still requires reconciling its school record against the CBT transfer ledger.

For a missing active-term result configuration, `php tasks/cbt_prepare_term.php` previews reuse of the latest configuration. With school authorization, `php tasks/cbt_prepare_term.php --reuse-previous` copies it once, keeps existing calendar/signature template values and opens the new term's score entry. It never overwrites an existing configuration. Local 1st Term 2026/2027 was configured at the user's request with CA 30 and exam 70; confirm school opening days, resumption and signature in Result settings. The established grading logic remains unchanged.

Regression checks: `node tests/cbt_exam_client_test.js`, `php tests/cbt_authoring_test.php`, `php tests/cbt_start_http_test.php`, `php tests/cbt_cookie_test.php`, `php tests/cbt_security_test.php` and `php tests/http_portal_audit.php cbt`. The start HTTP check uses an already exhausted demo paper and creates no attempt.

## Landscape midterm reports

Open **Academics → Mid-term results**, select the academic term and recorded class, then choose a learner or leave **Whole class** selected. **Preview report sheets** opens the landscape layout; **Download PDF** exports the selection. The preview also offers printing and individual learner links within a class batch. Browser printing uses the same A4 landscape sheets and can save to PDF.

The report reads Week 1-6 records from `lhpweekrecord`, using the historical class stored with those records. Learners who have moved class remain in their recorded class. Class export includes learners with weekly records for the selected period, sorted by name. It does not create or publish scores. The original formula remains `(W1 + W2 + W3 + W4 + W5 + W6) / 2`, with a maximum of 30 marks per subject and the original A-F grade thresholds. A recorded zero is shown as zero; unrecorded weeks show a dash and contribute zero, with an unrecorded-entry count in the summary. Duplicate or out-of-range weekly scores must be reviewed before export.

The school logo is resolved from the profile image directory. Blank, missing and legacy `nopix` learner photos use a student icon. Up to 16 subjects appear on a sheet; additional subjects continue on numbered landscape sheets with the learner header repeated. Combined PDF generation renders each sheet separately so long class batches do not exceed one large browser canvas or silently drop pages. The bundled PDF library stays local; if unavailable, the print/save-PDF path remains usable. The SCHELPS backlink stays on the admin pages and is excluded from the printed academic sheet.

Deploy `admin/mgmid.php`, `admin/viewmidterm.php`, `classes/MidtermReportService.php`, the updated autoloader, `views/shared/midterm-sheet.php`, `assets/css/midterm-report.css`, `assets/js/midterm-report.js` and both placeholder SVGs in `assets/images/` together. Keep the existing local `assets/js/html2pdf-loader.js` and `js/html2pdf.bundle.min.js`. No database migration is required. Main administrators and Registry Admin retain access; Bursary Staff cannot export academic reports. Full-term portrait reports and the separate learner-portal result flow are unchanged.
